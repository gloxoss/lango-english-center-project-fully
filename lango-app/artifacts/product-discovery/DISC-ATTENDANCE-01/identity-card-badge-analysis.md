# Identity, cards and QR badges — DISC-ATTENDANCE-01

## What exists
- Student identity: `user` row (role student) + matricule (generated by `libs/services/matricule.ts`, tenant format e.g. STU-…).
- Badge credential: `identity_badge_credentials`, one active per user (issuance revokes the previous one — badge-service.ts).
- Cards & convocations: separate cards module (`/dashboard/cards/students`), renders printable cards; not traced in depth here.

## What the QR contains
`LANGQR-STU-` + 32 random hex characters (16 random bytes) — a random bearer token (badge-service.ts:18-19). The database stores only `HMAC-SHA256(token, BETTER_AUTH_SECRET)` (badge-crypto.ts:22). Production refuses to run without the secret.
- `ATL-STU-0170` = `displayPrefix` of **seeded** rows. Real badges get `LANGQR-STU-x` (first 12 chars of the token). The seed format never occurs in real use.
- Not the matricule, not the DB id, not signed/encrypted data: an opaque random token checked by hash lookup.

## "HMAC-SHA256 Chiffrement Actif"
HMAC is a keyed hash (integrity/authentication), not encryption. The label is wrong and too technical. Suggested plain wording: "Badge sécurisé" / "Code unique, non devinable".

## Lifecycle
| Question | Answer |
|---|---|
| Revoke | Yes (status revoked, revokedAt) |
| Expire | Column exists (220 of 221 badges have a date) but **never checked by the scanner** (verify-and-stage: 0 references to expiresAt) |
| Reissue | Yes (/replace); invalidates the previous one (status replaced/revoked) |
| Raw secret stored | No (hash only) |
| Copyable | Yes — static QR; a photo of it works. Duplicate scans in the same scanner session are de-duplicated |
| Multiple per student | One active at a time; revoke+insert not in one transaction (tiny race) |
| Student card contains the QR | Not verified in this campaign |

## Recommendation (for review)
**MERGE** "Badges QR" into one "Cartes & badges" area inside Cards & Convocations: identity = student/matricule; the QR badge is a credential printed on the card. Keep issuance/revocation/reissue as actions on the card, not a separate page. Reason: two pages manage the same physical object; the badge page exposes technical terms; attendance only needs "is this credential active for this student".
