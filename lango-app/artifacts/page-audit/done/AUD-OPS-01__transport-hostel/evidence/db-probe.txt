--- 1. Column type and driver shape (F-08) ---
SELECT pg_typeof(expected_return_at) FROM hostel_leave_passes;
  -> timestamp without time zone

SELECT expected_return_at FROM hostel_leave_passes LIMIT 3;   -- drizzle-equivalent
  RAW TEXT: "2026-09-21 00:00:00" typeof string

Drizzle's node-postgres session installs an identity type parser for TIMESTAMP
(node_modules/drizzle-orm/node-postgres/session.js: `getTypeParser` -> `(val) => val`),
and PgTimestampString.mapFromDriverValue returns strings unchanged. So in the app
`pass.expectedReturnAt` is Postgres TEXT: 'YYYY-MM-DD HH:MM:SS.mmm' — a SPACE
separator, no offset.

Confirmed by the UI round trip: the seeded pass was posted as
  startDateTime     2026-09-24T10:20:29.491Z
  expectedReturnAt  2026-09-24T16:20:29.491Z
and the resident screen renders 11:20:29 -> 17:20:29 (Casablanca, UTC+1), i.e. the
stored naive values are the UTC wall clock.

--- 2. The two comparisons disagree on the same instant (F-01) ---
A leave pass due LATER THE SAME DAY (stored '2026-09-24 23:00:00', now 12:07 UTC):

  SQL form (escalations-service.ts, correct):
    SELECT '2026-09-24 23:00:00'::timestamp < '2026-09-24T12:07:30.211Z'::timestamp;
    -> f          ("not overdue" — correct)

  JS form (tonight-service.ts, the bug):
    '2026-09-24 23:00:00' < '2026-09-24T12:07:30.211Z'
    -> true       ("overdue" — WRONG)

Same data, same instant, opposite answers. Root cause: Postgres text uses a space
where ISO uses 'T', and ' ' (0x20) < 'T' (0x54), so any same-day timestamp sorts
before every ISO "now" string.
