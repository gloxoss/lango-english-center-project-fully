# SchoolOS — Staging Environment & Pre-Release Deployment Runbook (Task T24)

**Target Host:** Dedicated or right-sized staging VPS  
**Domain:** `https://staging.schoolos.epioso.com`  
**Purpose:** Pre-production migration dry-runs, end-to-end user acceptance testing, and release staging  
**Compose Specification:** `docker-compose.staging.yml`

---

## 1. Environment Architecture & Isolation Principles

The staging environment mirrors production architecture in every dimension while maintaining strict isolation:

```
                                [ Cloudflare / Certbot HTTPS ]
                                              │
                                              ▼
                             [ Nginx Reverse Proxy (Port 443) ]
                                              │
                                              ▼
                [ staging.schoolos.epioso.com -> 127.0.0.1:3031 ]
                                              │
                                              ▼
                                 [ schoolos-staging-app ]
                                (Next.js 16 Production)
                                              │
                                              ▼
                                 [ schoolos-staging-db ]
                             (PostgreSQL 16 on Port 5433)
```

### Strict Isolation Rules
1. **Zero Production Data:** Staging uses purely synthetic Moroccan seed data generated by `src/scripts/seed-full.ts`. Under no circumstances is a production database dump restored to staging (violates CNDP Law 09-08).
2. **Dedicated Secrets:** `BETTER_AUTH_SECRET` and database passwords must never duplicate production values.
3. **Port Segregation:** Staging app binds to `127.0.0.1:3031` and staging database binds to `127.0.0.1:5433` (preventing port collision with production 3030/5432).
4. **Independent Docker Volumes:** Staging Postgres stores data in `schoolos_staging_postgres_data`.

## 2. Step-by-Step Staging Deployment Procedure

### Step 1: Pre-Flight Build & Quality Gates (Local Machine)
Before staging transfer, verify that all local checks pass:
```bash
# 1. Typecheck
npx tsc --noEmit

# 2. Multi-tenant isolation security scan
npx tsx scripts/check-tenant-isolation.ts

# 3. Unit and integration test suite
npm test
```

### Step 2: Build Staging Docker Images
```bash
# Build app container
docker build -t schoolos-app:staging -f Dockerfile .

# Build migration runner container
docker build -t schoolos-migrate:staging -f Dockerfile.migrate .

# Export and compress images
docker save schoolos-app:staging | gzip -9 > schoolos-app-staging.tar.gz
docker save schoolos-migrate:staging | gzip -9 > schoolos-migrate-staging.tar.gz
```

### Step 3: Transfer to Staging Host
```bash
scp schoolos-app-staging.tar.gz schoolos-migrate-staging.tar.gz docker-compose.staging.yml user@staging-host:~/schoolos-staging/
```

### Step 4: Load Images & Apply Migrations
```bash
cd ~/schoolos-staging

# Load container images
docker load -i schoolos-app-staging.tar.gz
docker load -i schoolos-migrate-staging.tar.gz

# Start Postgres & execute migration container
docker compose -f docker-compose.staging.yml up -d schoolos-staging-db
docker compose -f docker-compose.staging.yml run --rm schoolos-staging-migrate

# Start application server
docker compose -f docker-compose.staging.yml up -d schoolos-staging-app
```

## 4. Rollback Protocol

If a staging release fails health probes or breaks schema expectations:
```bash
# 1. Stop staging services
docker compose -f docker-compose.staging.yml down

# 2. Re-tag previous working staging image
docker tag schoolos-app:staging-previous schoolos-app:staging

# 3. Restart staging app
docker compose -f docker-compose.staging.yml up -d
```
