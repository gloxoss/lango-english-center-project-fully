# S-2 · SMS reminders page shows a false all-clear

**Severity: P1** · Source report: [2026-09-23-deep-visual-sweep.md](../../2026-09-23-deep-visual-sweep.md) · Pages affected: 1

**Code check (2026-09-23):** Not re-checked since the sweep.

## What is wrong

"Élèves à risque (0) · Tous les indicateurs sont au vert !" while the dashboard lists a family 14 days late. Header says "SMS : Simulation" while the channel card says "SMS Direct · Télécom Maroc".

## Why

`sms-reminders-view.tsx:238` reads `summary.data.atRiskStudents`; the dashboard summary now returns `watchlist.students` (a bounded preview), so the list is always empty.

## Fix

Add a dedicated at-risk endpoint (full list, class filter) and consume it. Show an error, never "au vert", when the fetch fails. Make simulation vs real sending unambiguous.

## Plan

1. Create `GET /api/communication/at-risk` (tenant-scoped, paginated, class filter).
2. Switch the view to it; add an error state.
3. Show one clear send-mode badge from the active connection.
4. Test: seed one late family, the page lists it.

## Done when

A late family appears on the page; a failed fetch shows an error.
