**Code check (2026-09-23):** STILL OPEN: event GET has no status/audience filter.

## What is wrong

Parent opening `/dashboard/events/<id>` sees the staff management page with "Modifier" and "Annuler l'événement" and the waitlist. Server blocks those actions.

## Why

`GET /api/addons/events/[id]` requires only `events.read` (held by parents/students); `getEventDetail` returns the full row with no status/audience filter.

## Fix

Non-staff: only published events whose audience includes them, else 404; route them to a read-only family view.

## Plan

1. Add status + audience filter for non-staff in the GET.
2. Role-based view selection in the page.
3. Test: parent GET on a draft event returns 404.

## Done when
