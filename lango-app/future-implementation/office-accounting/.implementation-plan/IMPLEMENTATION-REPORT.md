## Delivered

- Extended the existing authoritative double-entry ledger; no duplicate ledger was introduced.
- Migration 0085: journals, voucher types, locked numbering series, versioned/idempotent posting requests, provenance/reversal links, immutable voucher events.
- Migration 0089: expense/deposit/manual source documents, balanced lines, maker-checker lifecycle, duplicate supplier-reference protection, immutable events and tenant-composite foreign keys.
- Migration 0090: tenant-safe reconciliation matches that preserve posted journal immutability.
- Migration 0093: chart-of-accounts mutation guard — used/parent accounts cannot be deleted, `account_type` cannot change once an account has posted lines, and an account can only be archived (is_active=false) with zero net balance and no active children.
- Migration 0097: period close/reopen — close writes an immutable ledger snapshot (`accounting_closing_runs` + `accounting_closing_balances` with balanced totals) as reproducible as-of evidence; reopen is a two-step maker-checker flow (`accounting_period_reopen_requests` — request with mandatory reason, then approve/reject by a different actor holding the exceptional `accounting.period.reopen` capability; approval reopens the period and supersedes the snapshot); every close/request/decision lands in the immutable `accounting_period_events` audit log. Statements accept `runId` to read the pinned snapshot instead of recomputing.
- Migration 0098: bank/cash reconciliation statement artifacts — `accounting_statement_imports` (SHA-256 `content_fingerprint` + `UNIQUE(tenant,reconciliation,fingerprint)` replay guard), `accounting_statement_lines` (one-sided debit/credit CHECK, `unmatched`/`partial`/`matched` status), `accounting_statement_matches` (pair-unique, `matched_amount > 0`, over-match guards on both sides), `accounting_reconciliation_events` (immutable lifecycle audit), and deferred post-close immutability triggers covering every statement artifact once the reconciliation is `completed`.
- Reconciliation service (`reconciliation-service.ts`): bounded RFC-4180 CSV parse (1MB / 5k-row limits, header/date/amount validation), replay-safe import (identical content → `alreadyImported`, race → 409), match/unmatch/split/merge with exact-cent over-match guards, controlled fee/interest postings through the central posting service (asset-offset account validation, unique `sourceDocumentId` per posting), and signed close (blocks unmatched/partial lines and unexplained variance, race-guarded, idempotent re-close). 8 API routes under `/api/finance/bank-reconciliation/[id]/`.
- Migration 0103: Student Accounting posting adapter — `accounting_source_mappings` resolves student sources to the chart of accounts with a per-type default (NULL `source_key`, exactly one enforced by a partial unique index) and tenant-composite FK to accounts; `accounting_adapter_exceptions` is a no-suspense block queue (unique per tenant+source+version, `open`/`resolved`/`dismissed` lifecycle) holding the exact would-be payload so an accountant can fix the mapping and retry.
- Student-accounting adapter service (`student-accounting-adapter.ts`): `postStudentInvoice` (Dr receivable = net, Cr revenue split across fee categories by exact largest-remainder cents) and `postStudentPayment` (Dr bank via `payment_method`, Cr receivable) both post through the canonical posting service with idempotency keys `student_<module>:<tenant>:<doc>`; a missing mapping blocks with an explicit exception and never a guessed account; successful re-post auto-resolves the open exception; `studentLedgerReconciliation` reports per-document state (posted/blocked/pending), summary totals and drift. 6 API routes under `/api/finance/accounting/student-accounting/` (mappings CRUD, post, exceptions, reconcile).
- WA2 discovery: the core ledger invariants (one-sided lines, ≥2 lines + exact balance at COMMIT, posted-entries/lines immutability, open-period + same-tenant account scope) were **already enforced at the DB layer by migration 0039 for all sources**; the posting service layered exact-cent validation, idempotency and numbering on top. 0093 therefore adds only the genuinely missing account-level guards, and the 0093 verifier proves every invariant adversarially.
- Central posting service: exact minor-unit arithmetic, open-period and tenant/account validation, payload digest, advisory locks, deterministic journal number, atomic entry/lines/link/event, retry replay and reversal.
- Versioned posting contract (WA6): `postAccountingVoucher` returns `postingRequestId` and a top-level `entryNumber` on both the fresh and idempotent replay paths (the request id is read back from `accounting_journal_links` on replay); `POSTING_CONTRACT_VERSION = '1.0'` with exported `AccountingPostingInput`/`AccountingPostingResult` types; [`POSTING-CONTRACT.md`](POSTING-CONTRACT.md) documents replay/source-version semantics, the canonical Payroll journal skeleton, reverse handoff and the latent IR rounding drift.
- Financial reports (WA7): `statements/general-ledger` (account-level opening/movement/closing with `from`/`to`), `statements/cash-flow` (indirect treasury bridge — operating + financing = Δ treasury, `reconciled` flag; treasury = asset accounts with PCG Class-5 codes), `statements/drill-down` (bounded account drill-through with running balance, capped at 1000 rows), the balance sheet now presents the period result inside equity and returns a `balanced` flag (A = L + E + result), and `?format=csv` on all statement types + trial-balance gated by the `accounting.export` capability.
- Fine-grained `accounting.*` capabilities with accountant defaults.
- Guarded APIs for accounts, journals, voucher types, transactions, drill-down, posting, reversal, deposits, expenses, trial balance, P&L and balance sheet.
- Page-guarded screens for accounts, journal/voucher setup, deposits, expense draft, expense workflow and general ledger.
- WA8 UI pages: `finance/accounting/student-accounting` (source mappings CRUD, no-suspense exception queue with resolve/dismiss, source→ledger reconciliation), `finance/accounting/statements` (balance générale / grand livre / compte de résultat / bilan / flux de trésorerie with period filters, per-account drill-through and CSV export) and `finance/accounting/periods` (create, close with mandatory reason, two-step maker-checker reopen: request then approve/reject queue). A GET `/periods/[id]/reopen-requests` route exposes the reopen-request queue to the UI. All three registered in the Finance sidebar.
- Full bank-reconciliation lifecycle UI (`src/features/finance/ui/bank-reconciliation-view.tsx`): per-reconciliation detail workspace with CSV import (bounded, replay-safe), a selectable statement-lines table with status badges, the bank asset account picker + drill-down journal lines, match (full or partial amount), unmatch, split (multi-part with per-part amounts), merge (≥2 statement lines onto one journal line), a fee/interest posting form (kind, amount, bank asset account, offset charge/revenue account, journal + voucher type, idempotency key), a signed close with explicit variance reason and an immutable events log — every action drives a 0098 route behind the `accounting.reconcile` capability.
