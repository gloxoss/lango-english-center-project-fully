# Section 07: Wire HMAC-Signed Download URLs

## Overview
Connects the already-correctly-built `SecureDownloadService` (HMAC-SHA256, `timingSafeEqual`) into the actual download route, which the audit found never checks it at all - closing the gap between the audit report's fabricated "signed download URL" claim and reality.

## Risk: yellow - the hard cryptography work already exists and is correct; this is wiring, not building new crypto

## Dependencies
- Depends on: section-02 (download route already rewritten), section-05 (real files to actually download)
- Blocks: section-10
- Parallel batch: 3

## TDD Test Stubs
- Test: A download URL includes a real HMAC signature and expiry, generated by `SecureDownloadService.generateSignature()`.
- Test: A download request with a valid, unexpired signature succeeds.
- Test: A download request with a tampered or expired signature is rejected, verified live via a real HTTP request with a deliberately wrong signature.
