# Assessment & Examination — M13 De-Mock — Product Requirements

> Generated by UltraPlan | 2026-08-14

## What We're Building

We're making the assessment screens honest. The school's exam tools already work behind the scenes — homework, exam terms/halls/seats/schedules, marks and rankings, and the simple multiple-choice online exam flow are all real and live. But two of the three on-screen pages lie about what they do. The "Online Exams" page shows fake numbers ("248 questions", "18 candidates online", "92% auto-correct") and a demo quiz that never saves anything. The "Homework" page mixes real data with two hardcoded sample assignments and a fake student submission. We're replacing that with real data and removing the fiction.

## The Problem

A previous pass claimed the exam tools were "100% deployed" while the online-exams page was still a static demo and the homework page still shipped fake sample rows. Separately, a richer "online examinations addon" (question bank authoring, live monitoring, accommodations) was started but would have collided with the real database table — that addon has already been formally retired, yet the online-exams page still advertises its features as if they existed.

## Who It's For

**Teachers / exam administrators**: create and grade homework, set up exam terms/halls/schedules, and author simple multiple-choice online exams — all against real data.

**Students**: take a multiple-choice online exam and get a real auto-scored result.

## What It Does

### Must Have
- Online Exams: list, create, and fill in a simple multiple-choice online exam with real questions and options, persisted through the live `/api/academics/online-exams/*` routes.
- Online Exams: a student can start and submit an attempt and receive the real auto-scored result — no hardcoded "18.0 / 20".
- Online Exams: remove every fake metric and the retired-addon labels ("live monitor", "question bank studio", "92% auto-correction", "anti-cheat masking").
- Homework: the page shows only real homework from `/api/academics/homework`, with a genuine empty state when there is none — no `hw-demo-*` seed rows.
- Homework: remove the fake student-submit action that posts `studentId: 'student-demo'`; keep the real teacher create/grade flows.
- Exam Master: confirmed working against a real tenant (already wired).

### Explicitly Not Building
- The retired rich online-exam addon (question bank versioning, blueprints, server-timed autosave runner, live candidate monitor, accommodations, QTI import/export, manual-grading queue). That decision is already made and is not revisited here.
- A new student-facing homework submission UI — that belongs in the student portal and is out of M13 scope.

## How It Should Feel

The pages keep their current look. The only visible change is that numbers and actions are real: creating a question actually persists it, submitting a quiz returns a real score, and there are no phantom sample rows or impossible "88% submission rate" badges.

## What It Connects To

No new outside connections. Online Exams reuses the existing legacy MCQ routes; Homework reuses the existing homework routes; Exam Master is already wired.

## What It Does NOT Do

- Does not add any new database tables, migrations, or backend services.
- Does not resurrect the retired parallel online-exam system.
- Does not build the student portal's homework view.

## How We'll Know It Works

- Creating an online exam + a question + an option persists and reloads from the real database.
- Submitting an attempt returns the real computed score, not a hardcoded value.
- The online-exams page contains no hardcoded question text, counts, or candidate names.
- The homework page shows zero rows when the API returns an empty list (no demo seed).
- The homework page has no code path posting `studentId: 'student-demo'`.
- Exam Master still creates a term, allocates seats, and saves marks against a real tenant.
- All of the above holds for a second, separate tenant with no cross-tenant leakage.

## Risks & Concerns

1. **The online-exams rewrite must match the legacy route shapes exactly** — the existing routes (`online-exams`, `[examId]/questions`, `submit`) are the only source of truth; the page must not invent fields they don't return.
2. **Removing the student-submit flow from the teacher homework page is a judgment call** — it was a fake demo, but if a real student-facing submit flow is expected soon, the student portal owns it, not this teacher page.
3. **Same standing rule as every pass**: nothing is trusted as done until it's exercised against the real running app and real database, for two tenants.
