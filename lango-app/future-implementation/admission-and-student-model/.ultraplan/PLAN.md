## Architecture Overview

Next.js 16 App Router + Drizzle ORM + PostgreSQL + Better Auth, matching the rest of this codebase exactly — no new framework or library is introduced. The core architectural addition is a small `applicantDocuments` table (mirrors the existing `studentDocuments` table) to give the admission wizard a real place to save uploads before a student record exists, plus a copy-forward step at approval that moves those files onto the real student. Guardian linking reuses the existing `guardians`/`guardianStudents` tables and search pattern already proven in `parents-guardians-view.tsx`, inlined into the approval transaction rather than called over HTTP (since it must be atomic with student creation). Login-access generation is the one genuinely new mechanism, built on Better Auth's server-side account-creation API with a small `accountSetupTokens` table for the invite-link path.

## Tech Stack
- Frontend: Next.js 16 App Router, React, Tailwind v4 (existing)
- Backend: Next.js API routes, Drizzle ORM (existing)
- Database: PostgreSQL, via Docker Compose (existing)
- Auth: Better Auth (existing, extended with programmatic account creation — new usage, not a new library)
- Storage: local disk under the `schoolos_uploads` Docker volume via `src/libs/api/uploads.ts` (existing, extended with a copy helper)
- Delivery: log-only simulated `smsMessages` (existing convention, no new gateway)
